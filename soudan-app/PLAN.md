# 住宅再建無料相談会 受付・待ち行列共有アプリ 計画書

主催: 九州財務局 / 対象: 令和8年熊本地震の被災者 / 開催: 2026年12月初旬(1会場・1日・相談者約100人)

## 1. 目的
受付、待ち行列、どの相談先へ相談したか、帰宅状況を、職員全員がスマホで共有できるようにする。
待ち時間の掲示は従来どおりホワイトボードに手書きし、アプリはその根拠となる数字を出す。

## 2. 確定事項
| 項目 | 内容 |
|---|---|
| 利用者 | 職員のみ(個人のスマホ)。相談者向け画面はなし |
| 認証 | 共通パスコード + URL配布(当日朝に周知) |
| 取得情報 | 苗字、携帯電話番号、メモ(最小限)。当日の呼び出し連絡用 |
| 同意 | 当日の案内。パンフに記載し、口頭で説明。アプリ内に同意確認チェックを置く |
| 削除 | 相談会終了後、速やかに全削除(管理画面のボタン) |
| 相談時間 | 1回約20分。実績の平均で自動補正 |
| 待ち時間表示 | ホワイトボードは手書き。アプリは「(1+待ち人数)×20分−相談経過時間」を参考値として表示 |
| 相談先 | 14団体。建築士事務所協会と弁護士会は2ブース(同時対応数2)、他は1 |
| 優先対応 | 不要(割り込み機能は作らない) |

相談先(初期値): 熊本県信用組合 / 天草信用金庫 / 熊本中央信用金庫 / 熊本第一信用金庫 / 熊本信用金庫 / 熊本弁護士会(2) / 肥後銀行 / 熊本銀行 / 住宅金融支援機構 / 九州労働金庫 / JA八代 / 八代市 / 建築士事務所協会(2) / 賃貸住宅経営者協会

## 3. 業務の流れ
1. 受付で相談者を登録(苗字・携帯番号・最初の相談先)し、受付番号(例: 001)を発行する。紙の番号札を渡す。
2. 待ち札(相談者×相談先)が相談先の行列の最後尾に入る。
3. 相談先が空いたら、先頭の人を職員が案内し「相談開始」を押す。
4. 終了したら「相談終了」を押し、次へ進むか選ぶ。
   - 別の相談先へ: 受付し直して、その行列の最後尾に並ぶ
   - 帰宅: 相談を持ち帰ったかどうかを記録して終了
5. 途中で帰る人は「途中離脱」として、待ち札を取り消す。
6. 相談先の追加・休止は管理画面から行う。

## 4. データモデル
- visitor: 受付番号、苗字、携帯番号、状態(会場内 / 帰宅)、帰宅区分(完了 / 持ち帰り / 途中離脱)、メモ、受付時刻
- desk: 名称、同時対応数(ブース数)、状態(受付中 / 休止)、表示順
- ticket: visitor、desk、状態(待機中 / 相談中 / 完了 / 取消)、並んだ時刻、開始時刻、終了時刻、ブース番号
- 並び直しのたびに新しい ticket を作る。これで履歴(どこを回ったか)と、最後尾への並び直しを両立する。
- 待ち人数 = 状態が待機中の ticket 数。平均相談時間 = その相談先の完了済み ticket の平均(実績が3件未満なら20分を使う)。
- 目安待ち時間 = (1 + 待機人数) × 20分 − 相談中の人の経過時間(例: 15分経過・待ち3人 → 65分)。20分は固定で、実績平均は使わない(実績平均はブース画面・ボードの表示用)。複数ブースは最も早く空くブースへ順に割り当てる。

## 5. 画面
1. **ボード(トップ)**: 14相談先を一覧し、各相談先の「相談中 / 待ち人数 / 目安待ち時間」を表示。ここからの更新は全員にリアルタイム反映。
2. **受付**: 苗字・携帯番号・相談先を選んで受付番号を発行。同意確認チェックあり。
3. **相談先画面**: 行列の先頭から「案内して開始」「終了」を操作。終了後に次の相談先 / 帰宅を選ぶ。
4. **相談者一覧・検索**: 受付番号・苗字で検索。回った相談先の履歴、現在地、電話をかけるボタン(tel:)。
5. **管理**: 相談先の追加・休止・ブース数変更、パスコード変更、全データ削除(確認2段階)、監査用に操作ログ。

## 6. 技術
- スマホ向けWebアプリ(PWA)、TypeScript + React + Vite を想定。
- リアルタイム同期は Supabase(Postgres + Realtime)を想定。100人規模なので無料枠で足りる。
- パスコード認証は共通パスコードを検証してセッションを発行する。DB は匿名アクセス不可(行レベルセキュリティ)とし、パスコードを知らない人からは読めない。
- 通信が切れたときは画面上部に警告を出し、再接続時に自動で再同期する。操作は同期完了まで押せないようにして二重登録を防ぐ。
- 画面は1ボタンの操作を基本とし、誤操作時は直前の操作の取り消しを用意する。

## 7. 個人情報の取り扱い
- 取得は苗字と携帯番号のみ。メモ欄は短い文字数に制限し、注意書き(相談内容など詳細は書かない)を表示する。
- 通信は HTTPS のみ。パスコードは当日朝に周知し、終了後に無効化する。
- 相談会終了後、速やかに管理画面から全データを削除する。削除後の確認手順を運用メモにまとめる。
- 個人情報の削除責任者と、パスコードを知る職員の範囲は主催側で決めておく。

## 8. 進め方(12月初旬の開催まで)
1. 画面と運用フローの確認(ワイヤーフレーム)
2. データ設計と同期基盤の構築
3. 受付、相談先画面、ボード、相談者検索の実装
4. 管理(削除・相談先設定)とテスト
5. 職員による模擬運用(100人規模を想定した試験)
6. 当日の運用マニュアルと、予備手順(紙とホワイトボードへの切り戻し)の作成

## 9. 追加で確定した事項
- 電話番号は職員が電話をかけて呼び出すだけで、SMSは送らない(タップで発信)。
- 会場Wi-Fiはなく、職員のスマホ回線(モバイル通信)を使う。電波が弱い場所があり得るため、通信断に強く作る(下記)。
- 技術は TypeScript + React + Vite + Supabase で進める(お任せ)。
- 共用端末はなく、受付も相談先も職員のスマホで操作する。

## 10. 回線がWi-Fiなしであることへの対応
- 操作はまず画面に反映し、通信できたら送信する(未送信は件数を表示して再送)。
- 同じ相談者の二重受付・二重開始が起きても壊れないよう、操作ごとに一意のIDを付けて重複を無視する。
- 競合時(別の職員が先に案内済みなど)は、サーバーの状態を正として画面に知らせる。
- 通信量を抑えるため、必要な差分だけを同期し、画像などは使わない。
- 当日朝にアクセス用URLをホーム画面に追加(PWA)してもらい、会場で電波を試験する。
- 全体が落ちたときの切り戻し用に、紙の受付表(受付番号・苗字・相談先の記入欄)を印刷しておく。

## 11. 閲覧者(各相談先の職員、最大40名)の追加
- 利用者は「操作者(財務局の職員6名)」と「閲覧者(各相談先の職員など、操作者を含め合計40名程度)」の2種類にする。
- 認証は操作用と閲覧用の2種類のパスコードを分ける。閲覧用は各団体の担当者に配布し、操作用は財務局の6名だけが知る。
- 閲覧者は読み取り専用で、受付・開始・終了・並び直し・管理の操作は一切できない(画面にボタンを出さず、DBの権限でも拒否する)。
- 閲覧者に見せるもの: 受付番号、苗字、各相談先の待ち人数・相談中・目安待ち時間、相談者がどの相談先を回ったかの履歴。
- 閲覧者に見せないもの: 携帯電話番号、メモ、操作ログ、管理画面。電話番号とメモは操作者のみ。
- 他団体の職員にも苗字が見えるため、同意の案内(パンフと口頭)に「相談先の職員が受付番号と苗字を共有すること」を明記する。
- 閲覧者の画面は、ボードと相談者検索(番号・苗字)に絞る。自団体の相談先を先頭に固定表示できるようにする。
- 同時接続は最大40台。更新が多い画面なので、閲覧者には差分だけを配信し、一定間隔(数秒)でまとめて描画する。Supabaseの無料枠(同時接続200)の範囲に収まる。
- 当日の運用: 閲覧用URLとパスコードを事前に各団体へ配布し、当日の接続を試験する。

## 12. 実装状況と設計の確定
- 実装済み: 受付、ボード、相談先画面、終了後の次の行き先、相談者検索・履歴、管理(相談先・パスコード・全削除・操作ログ)、操作用/閲覧用の権限分け、通信断時の保存と再送。
- 更新の取得は3秒ごとのポーリングに確定(パスコード認証と相性が良く、40台でも負荷が小さい)。
- 権限判定と電話番号・メモの出し分けはDB側の関数で行い、テーブルは外部公開しない。
- 検証済み: DBテスト13件、ロジックテスト18件、スマホ画面の通し確認(受付→開始→終了→並び直し→オフライン→全削除)。
- 配置手順と開発手順は README.md を参照。

## 14. 仕様変更(第2版)
個人情報の取得を最小にするため、運用を次のとおり変更した。

- 取得する個人情報は苗字のみ。携帯電話番号は取得しない。呼び出しは口頭とホワイトボードで行う。
- 帰宅は「帰宅」の1種類のみ(持ち帰り・途中離脱の区別は廃止)。
- 相談先を「公的機関等 → 民間協会 → 金融機関」の順に並べ、区分ごとに色分けする。
- 弁護士会と建築士事務所協会は、ブースごとに①②の別々の相談先(行列も別々)として管理する。ブース数の設定は管理画面から外した。
- 受付で、最初に並ぶ相談先(1つ)と、希望する相談先(複数)を記録する。次の行き先は相談しながら決まるため、終了時に希望先を上に出すが、希望にない先にも並べる。
- 離席: 呼び出しても不在の場合は、その人と次の人の順番を入れ替える。
- 付け替え: 待ちの途中で別の相談先に移すときは、新しい行列の最後尾に入れる。
- ボード: 待ち1人=薄黄、2〜4人=薄赤から段階的に濃い赤、5人以上=赤。相談中の経過時間は大きく表示し、20分以上は赤で強調する。
- 不具合の修正: 全削除と、パスコード変更の一部が、Supabase のAPI経由では「WHERE のない UPDATE / DELETE」として拒否されていた。すべて where を付け、検査テストを追加した。

## 15. 仕様変更(第3版)
- 案内待ちの注意表示: ブースが空いていて待ちの人がいる相談先を、ボード先頭に赤枠で表示する。終了→次の行き先→次の人の案内を一連の画面で進める。
- 受付の同意確認チェックは廃止(同意は当日の案内で行う)。
- ボード最下部に、会場内・帰宅・受付累計の数表示を移した。待ち人数の数字は0以外を色付きにした。
- 離席: 相談者画面から、昼食などで待ち行列から外れる。外れている間に前の人が終わってブースが空けば、次に並んでいる人を先に案内することがあると説明し、了承を得てから操作する。戻ったら離席前の順番に戻る。離席中に後ろの人が先に案内されていれば、戻った人は残りの待ち行列の先頭(次の順番)になる(DBの待ち札の状態 away。順番の基準 queue_at は変えない)。
- ボードの相談先カードに「相談実績 ○件 / 平均○分」を表示し、開くと相談を終えた方の一覧(番号・苗字・所要分・終了時刻)が見える。
- 相談者の動きを登録する前に、登録内容の確認画面を出す: 案内して開始 / 次の行き先に並ばせる / 付け替え / 帰宅。「やめる」で登録しない。(離席は説明つきの確認画面が既にある)
